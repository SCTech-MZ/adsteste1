O que é JSON e como utilizá-lo?

JSON é o formato de dados mais usado na web. Este guia explica a sua estrutura, as regras de sintaxe que não podem ser ignoradas e os erros que aparecem com mais frequência quando se edita um ficheiro à mão.

Definição

JSON significa JavaScript Object Notation. É um formato de texto para representar dados estruturados, definido na norma RFC 8259. Apesar do nome, não é exclusivo do JavaScript: praticamente todas as linguagens modernas conseguem ler e escrever JSON.

O objetivo do formato é ser simples para humanos e trivial para máquinas. Um documento JSON é apenas texto, o que o torna fácil de transmitir por HTTP, guardar num ficheiro ou incluir numa mensagem.

Os seis tipos de valores

Em JSON só existem seis tipos de dados:

  • Objeto — conjunto de pares chave-valor entre chaves { }
  • Array — lista ordenada de valores entre parênteses retos [ ]
  • String — texto entre aspas duplas
  • Número — inteiro ou decimal, sem separadores de milhares
  • Booleano — true ou false
  • null — ausência de valor

Não existem datas, funções, comentários nem valores indefinidos. Uma data representa-se habitualmente como texto em formato ISO 8601, por exemplo "2026-01-18".

Um exemplo completo

{
  "pedido": 1042,
  "cliente": {
    "nome": "Ana Silva",
    "email": "ana@exemplo.com",
    "pais": "MZ"
  },
  "artigos": [
    { "descricao": "Teclado", "quantidade": 1, "preco": 39.9 },
    { "descricao": "Rato", "quantidade": 2, "preco": 12.5 }
  ],
  "pago": false,
  "notas": null
}

Este documento tem um objeto na raiz, um objeto aninhado em cliente e um array de objetos em artigos. A estrutura pode ser aninhada tantas vezes quantas forem necessárias.

Regras de sintaxe obrigatórias

  • As chaves e as strings usam obrigatoriamente aspas duplas. Aspas simples são inválidas.
  • Os pares chave-valor são separados por vírgulas, mas nunca pode existir uma vírgula depois do último elemento.
  • Os comentários não fazem parte do formato. Um ficheiro com // ou /* */ não é JSON válido.
  • Os números não podem começar por +, nem ter zeros à esquerda, nem usar separadores de milhares.
  • Dentro de uma string, as aspas duplas e as barras invertidas têm de ser escapadas com \" e \\.
  • Um documento tem de ter exatamente um valor na raiz. Dois objetos seguidos não formam um JSON válido.

Erros mais comuns

Vírgula final

É o erro número um, especialmente quando se acrescenta ou remove um campo à mão. Remova a vírgula que aparece imediatamente antes de } ou ].

Aspas simples

Vindo de JavaScript ou Python, é natural usar 'aspas simples'. Em JSON, todas as chaves e strings usam aspas duplas.

Campos sem aspas

Em JavaScript, { nome: "Ana" } é válido. Em JSON, a chave tem de ser "nome", com aspas duplas.

Comentários

Se o ficheiro é uma configuração que precisa de comentários, use antes um formato que os suporte, como JSONC ou YAML. Para uma API, os comentários devem ser removidos.

Objetos concatenados

Se tem vários registos, coloque-os dentro de um array: [ { ... }, { ... } ]. Concatenar dois objetos com uma vírgula entre eles origina um erro de sintaxe.

Caracteres invisíveis

Textos copiados de processadores de texto podem conter aspas curvas (" ") ou espaços que não são espaços normais. Nesse caso, a validação falha num ponto que parece correto à vista.

Onde o JSON é usado

  • APIs REST: é o formato padrão dos corpos de pedido e de resposta.
  • Ficheiros de configuração: package.json, tsconfig.json e muitos outros.
  • Bases de dados documentais: MongoDB e serviços semelhantes guardam documentos em BSON, uma representação binária de JSON.
  • Armazenamento local no navegador: localStorage só guarda texto, pelo que objetos são normalmente serializados em JSON.
  • Intercâmbio de dados entre serviços: é uma alternativa mais leve ao XML.

Boas práticas

  • Formate antes de revisão. Uma indentação consistente torna os erros estruturais muito mais visíveis.
  • Use nomes de chaves descritivos e mantenha um padrão consistente (por exemplo, sempre camelCase).
  • Não coloque dados sensíveis em ficheiros JSON versionados em repositórios públicos.
  • Minimize apenas no fim. Minificar reduz o tamanho, mas torna a leitura impossível. Faça-o como último passo antes de transmitir ou guardar.
  • Valide sempre a entrada. O facto de um documento ser JSON válido não significa que tenha os campos esperados.

Resumo

  • JSON é um formato de texto com seis tipos de dados.
  • As chaves e as strings usam sempre aspas duplas, e não há comentários nem vírgulas finais.
  • Formatação e validação poupam tempo na depuração de APIs.
  • Minificar reduz o tamanho; formatar melhora a legibilidade. Use cada um no momento certo.
