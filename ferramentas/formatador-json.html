Como usar o formatador JSON

  1. Cole o JSON na caixa JSON de entrada ou carregue um ficheiro .json.
  2. Escolha a indentação pretendida (2 espaços, 4 espaços ou tabulação).
  3. Clique em Formatar para organizar o documento, Minificar para remover todos os espaços desnecessários ou Validar para apenas verificar a sintaxe.
  4. Se existir um erro, aparece uma explicação com a linha, a coluna e o ponto exato do problema.
  5. Copie o resultado com Copiar ou limpe tudo com Limpar.

O que é JSON

JSON (JavaScript Object Notation) é um formato de texto para representar dados estruturados. Foi definido na norma RFC 8259 e tornou-se a linguagem comum das APIs web, ficheiros de configuração e bases de dados documentais.

Um documento JSON é composto por seis tipos de valores: objetos, arrays, strings, números, booleanos e null. Um objeto é um conjunto de pares chave-valor entre chaves { }; um array é uma lista ordenada entre parênteses retos [ ].

Exemplo de JSON válido

{
  "produto": "Teclado",
  "preco": 39.9,
  "disponivel": true,
  "etiquetas": ["informática", "acessórios"],
  "detalhes": { "cor": "preto", "garantia": null }
}

Regras essenciais da sintaxe

  • As chaves e as strings usam obrigatoriamente aspas duplas. Aspas simples não são válidas.
  • Os pares chave-valor são separados por vírgulas, mas não pode existir vírgula depois do último elemento.
  • Os comentários não fazem parte do formato. Um ficheiro com // ou /* */ não é JSON válido.
  • Os números não podem começar por + nem usar separadores de milhares. Zero à esquerda também não é permitido.
  • Os valores devem ser um dos seis tipos suportados. Funções, undefined e datas não existem em JSON.

Erros mais comuns e como os resolver

Vírgula final

É o erro mais frequente, sobretudo em objetos editados à mão. Remova a vírgula que aparece imediatamente antes de } ou ].

Aspas simples

Vindo de JavaScript ou Python, é natural usar aspas simples. Em JSON, substitua todas por aspas duplas. Se a string já contiver aspas duplas, escape-as com \".

Comentários

Se o ficheiro é uma configuração que precisa de comentários, considere JSONC ou outro formato. Para uma API, os comentários devem ser removidos.

Objetos concatenados

Dois documentos JSON no mesmo ficheiro não formam um JSON válido. Coloque-os dentro de um array para os agrupar.

Casos de uso prático

  • Depurar respostas de API: formate a resposta para inspecionar rapidamente a estrutura e a profundidade dos objetos.
  • Reduzir payloads: minifique antes de guardar dados num campo de texto limitado ou de os enviar por um canal restrito.
  • Revisão de configurações: valide ficheiros de configuração antes de os aplicar num serviço.
  • Comparar versões: com as chaves ordenadas, as diferenças entre duas versões tornam-se muito mais fáceis de identificar.

Perguntas frequentes

O JSON é enviado para algum servidor?

Não. A validação e a formatação são feitas no seu navegador com JSON.parse e JSON.stringify. Nenhum conteúdo é transmitido, pelo que pode validar payloads internos com segurança.

Quais são os erros de JSON mais comuns?

Os erros mais frequentes são vírgulas a mais antes de uma chave de fecho, aspas simples em vez de aspas duplas, chaves sem aspas, comentários e vírgulas finais.

Porque é que o JSON não aceita comentários?

O formato JSON, definido na norma RFC 8259, não inclui comentários. Se precisar de comentários, use JSONC ou um ficheiro de configuração próprio, mas não os envie como JSON válido para APIs.

A ferramenta usa eval()?

Não. Apenas JSON.parse é usado, o que significa que o conteúdo é tratado como dados e nunca como código.

Qual é o tamanho máximo do documento?

Não existe um limite imposto pela ferramenta para texto colado. O carregamento de ficheiros está limitado a 5 MB para manter o navegador responsivo.

As chaves ordenadas alteram o significado do documento?

Não. Em JSON a ordem das chaves de um objeto não tem significado semântico. Num array, a ordem é relevante e nunca é alterada.
